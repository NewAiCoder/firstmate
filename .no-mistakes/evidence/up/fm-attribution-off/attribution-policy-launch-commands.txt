Actual literal shell command fm-spawn.sh sends via `tmux send-keys` to launch a
claude worker, captured from the crewmate and secondmate attribution-policy
tests (tests/fm-spawn-dispatch-profile.test.sh) via `bash -x`.

=== claude crewmate launch ===
env -u CURSOR_AGENT -u CURSOR_INVOKED_AS -u GEMINI_CLI CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION=false CLAUDE_CODE_SEND_FEEDBACK=0 claude --dangerously-skip-permissions --settings '{"feedbackDrafts":"off","attribution":{"commit":"","pr":"","sessionUrl":false}}' "$(...encode launch-brief < launch-brief.md)"

=== claude secondmate launch ===
FM_ROOT_OVERRIDE= FM_STATE_OVERRIDE= FM_DATA_OVERRIDE= FM_PROJECTS_OVERRIDE= FM_CONFIG_OVERRIDE= FM_PUBLIC_FOLLOWUP_PRIMARY_HOME='...' FM_HOME='...' FM_TRACE_CONTEXT=off FM_SUPERVISION_MODEL=autoarm CLAUDE_CONFIG_DIR='...' env -u CURSOR_AGENT -u CURSOR_INVOKED_AS -u GEMINI_CLI CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION=false CLAUDE_CODE_SEND_FEEDBACK=0 claude --dangerously-skip-permissions --settings '{"feedbackDrafts":"off","attribution":{"commit":"","pr":"","sessionUrl":false}}' "$(...encode launch-brief < charter.md)"

Both paths now carry --settings '{"attribution":{"commit":"","pr":"","sessionUrl":false}}'
regardless of which settings scopes the spawned worker loads, so a spawned
crewmate or secondmate can no longer write a Co-Authored-By trailer,
Claude-Session link, or generated-with line into a commit or PR body.
